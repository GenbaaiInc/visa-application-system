# 特定技能対応の実装状況（2026-09-14）

## 今回の範囲

特定技能の「新規入国（認定・COE）／変更／更新」を追加する。案件作成、資料アップロード、根拠の表示、担当者による修正という外枠は既存のまま使う。技人国の変更・更新は未対応のまま、技人国COEは従来処理を維持する。

設計を大きく共通化せず、特定技能の抽出項目・指示は独立したファイル、RASENS入力先は手続き別の3ファイルに分けた。氏名など意味が同じ既存項目だけを再利用する。将来の人材管理との統合やデータ移行は今回行わない。

## データの扱い

1. 資料をGeminiで読み、候補値と根拠を作る。特定技能は項目別抽出だけを使う。
2. 担当者が、雇用形態・支援方法と、空欄の必須項目・申告事項を確認する。
3. 確認後の案件データから、その手続きのRASENS入力行を作る。
4. Chrome拡張で入力する。写真添付・最終同意・申請送信は自動化しない。

表示条件を確定できていない一部の詳細欄は、誤入力を避けてRASENSで手入力する。対象は技能・日本語評価の試験名／受験地／その他根拠、海外取次機関、所属機関の副業種「その他」。資料から読める候補値と根拠はアプリで確認できるが、この範囲まで自動入力完了とは扱わない。

資料にない法令遵守・支援計画の適合申告を、AIで「はい／いいえ」にしない。技人国向けの入国港・在留期間・申告の既定値も特定技能へ流用しない。再抽出時も担当者の修正値と案件の手続き・在留資格は維持する。

旧golden、元資料、既存案件は変更・移行しない。実資料の検証は引き続き1案件（1人）ごとに行う。同じ人の変更資料と更新資料を別人として数えない。

## 入力対象の決め方

- 画面の「必須」印を基準にし、今回の対応で送信時エラーの網羅的な再現は要求しない。
- 1号／2号、直接雇用／派遣、委託／自社支援によって対象外の欄を除外する。RASENSに前の選択値が残っていても流用しない。
- 派遣先、雇用主、実際の勤務場所を別項目として持つ。雇用主の値を派遣先へコピーしない。
- 必須値が空欄、選択肢に合わない、担当者確認が必要な値が未確認の場合は自動入力を止める。
- 写真等のRASENS上で行う操作は、アプリ内の必須値不足とは分けて表示する。自動入力可能は「申請完了」や「許可される」の意味ではない。

## 検証と残る確認

バックエンドでは、3手続き×1号／2号、空欄の必須表示、条件外データの除外、派遣先と雇用主の分離、手動修正の保護、未対応抽出モードの拒否を合成データで検証する。これは実案件のAI抽出精度の数値ではない。

2026-09-16時点で、バックエンド361件と生成資産6件のテストが成功。旧案件の読込互換と再抽出時の分類保護、必須欄の確認後に3手続き×1号／2号・雇用形態・支援方法の18パターンで自動入力可能になる結合テストも含む。フロントエンドのビルド・静的チェックも成功した。

Geminiの出力schema上限を避けるため、特定技能のAI抽出は、本人情報と用途別の小さなscopeへ分けた。最終的な案件データの形は変えず、1号は9scope、2号は1号固有の支援scopeを除く7scopeを使う。個人情報を含まない実API試験は全scope成功し、変更65ページ・更新36ページの実資料でもscope失敗0件を確認した。詳細は[実資料スモークテスト](実資料スモークテスト_2026-09-15.md)を参照。

ブラウザの自動テストも40件成功（アプリ26件＋Chrome拡張14件）。案件作成、必須項目の編集・保存、既存技人国画面、非表示ラジオの可視ラベル操作、非表示・入力不可欄の除外、入力先ID／名前／種類の照合、変更と更新の対象資格判定、旧スクリプトとの混在防止を確認した。拡張の試験はRASENS構造を再現したローカル画面で実施し、本番サイトには送信していない。独自の擬似DOMテスト基盤は残さず、既存のブラウザテストへ集約した。

再実行は `visa-app/frontend` で `npx playwright test --output ../../qa/screenshots/2026-09-14/e2e-final`。検証用の出力はGit管理外の `qa/screenshots/` に置く。

実装担当と別担当のレビュー、および結合テストで、次を修正した。

- 再抽出で担当者の修正が上書きされる問題（繰り返し項目も含む）。
- 非表示の条件付き項目が、常に必須不足と判定される問題。
- 在留カードの受領方法とCOEのメール受領設定の混同。カードの受領方法・受領官署・住居地の都道府県は案件の選択欄に分離した。
- 親族生年月日の入力先、ラジオ選択肢の取り漏れ、1号／2号の希望在留期間候補の混入。

実資料では動作確認と主要識別情報の照合まで行ったが、全項目の正解率測定ではない。実申請の保存・送信は行っていない。派遣の実案件資料による照合も未実施であり、派遣欄の入力対応ができたことと抽出精度の保証は区別する。本番反映とChrome拡張の配布状況は[リリース記録](リリース記録.md)を参照。
