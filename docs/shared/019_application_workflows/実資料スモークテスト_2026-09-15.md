# 特定技能・実資料スモークテスト（2026-09-16更新）

## 結論

特定技能の大きなGemini schemaで発生していた `HTTP 400 INVALID_ARGUMENT` は、用途ごとの小さなscopeへ分けることで解消した。個人情報を含まないAPI試験に加え、同一人物の変更資料と更新資料を別手続きとして再実行し、全scopeが成功した。

これは「処理が最後まで動く」ことの確認であり、全項目の正解率や申請の許可を保証するものではない。本番反映、Firestore更新、RASENSへの入力・保存・送信は行っていない。

## 修正内容

- 共通の本人情報に加え、特定技能を `status / employer / contract / eligibility / dispatch / support organization / recruitment / self support` に分割した。
- 特定技能2号では、1号だけに必要な支援方法・登録支援機関・自社支援のscopeを実行しない。
- 認定（COE）では変更・更新用の希望在留期間と理由を抽出しない。変更と更新では、それぞれ該当する理由だけを抽出する。
- 申請入力に使わない所属機関事業所名、入社日、一般的な契約形態を特定技能schemaから外した。
- 一部scopeが失敗しても成功した値と失敗scopeを分けて返す既存の扱い、および最終的な案件データの形は維持した。

## APIと自動テスト

- 個人情報を含まない短い合成入力を実際のGemini APIへ送信した。
- 特定技能1号は9scope中9scope成功、2号は7scope中7scope成功。
- バックエンドテスト361件成功。3手続き（認定・変更・更新）×1号／2号について、scope間の項目重複がないこと、不要項目が除外されること、一部scope失敗時に残りの結果を保持できることを確認した。

## 実資料の結果

### 在留資格変更

- 「【特定技能】申請資料　変更.pdf」65ページを、変更・特定技能1号として実行。
- 約40秒。抽出メタデータ102項目、根拠参照付き50項目、RASENS入力候補45行。
- 抽出scope失敗は0件。

### 在留期間更新

- 「手続き申込：申込確認.pdf」と「追完資料2026 更新.pdf」の計36ページを、1件の更新案件として実行。
- 約33秒。抽出メタデータ100項目、根拠参照付き68項目、RASENS入力候補64行。
- 抽出scope失敗は0件。

いずれも組織設定と人の確認値を与えていないため、このローカル実行では自動入力可能にはならない。変更は必須不足76件、更新は56件だったが、これは抽出エラー件数や精度の誤り件数ではない。

本人の主要識別情報は変更・更新で整合した。国籍・所属機関・支援機関などには言語表記、書式、時点差の可能性があるため、自動的に同一値へ寄せず、人が原本と根拠を確認する。

## 残る確認

1. 担当者が主要な契約・所属機関・支援機関の値を根拠画像と照合する。
2. 派遣案件は、実際の派遣資料が得られた時点で派遣元・派遣先・勤務場所を照合する。
3. 本番へ反映した後、送信を伴わない1案件の動作確認を行う。
